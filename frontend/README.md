# Frontend

Mobile-first PWA for the Offline-First Itinerary Advisor. Travellers pick a heritage site, plan
a trip, download a trip pack once, and keep the advice on the phone when the signal drops.

Status: foundation only. The screens are placeholders and the on-device model is not built yet.

## Stack

| Concern | Choice |
|---|---|
| Build | Vite + React + TypeScript |
| Styling | Tailwind CSS v4 (`@tailwindcss/vite`) |
| Routing | React Router |
| Offline app shell | `vite-plugin-pwa` (Workbox service worker + web manifest) |
| Offline trip data | IndexedDB through `idb` |
| Lint | oxlint |

## Run it

Needs Node 20.19+ (developed on Node 24).

```sh
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Other scripts:

```sh
npm run typecheck  # tsc only
npm run build      # type check + production build into dist/
npm run preview    # serve dist/ on http://localhost:4173, with the service worker
npm run lint
```

The service worker is only generated by `npm run build`, so test offline behaviour with
`npm run build && npm run preview`. Then open DevTools > Application to check the service worker
and IndexedDB, and use the Network panel's "Offline" option to simulate no signal.

## Talking to the backend

The backend (owned by the backend team, in `../backend`) is deployed at
`https://offline-ai-trip-advisor.vercel.app`. **It does not send CORS headers**, so the browser
cannot call it directly. Instead the app calls `/api/...` on its own origin, and the Vite dev and
preview servers forward that to the backend (see `vite.config.ts`).

| Variable | Read by | Default | Purpose |
|---|---|---|---|
| `VITE_API_BASE_URL` | the app | `/api` | Base URL used by `src/api/client.ts` |
| `API_PROXY_TARGET` | `vite.config.ts` | the deployed backend | Where `/api` is forwarded, e.g. `http://127.0.0.1:8000` for a local backend |

Copy `.env.example` to `.env` to change them. `API_PROXY_TARGET` is a shell variable for the dev
server, e.g. `API_PROXY_TARGET=http://127.0.0.1:8000 npm run dev`.

**Production:** a static host has no Vite proxy. Either the backend adds CORS for the app's origin
(then set `VITE_API_BASE_URL` to the backend URL at build time), or the host rewrites `/api/*` to
the backend. This is not decided yet.

### Endpoints used

All in `src/api/client.ts`:

| Function | Request | Notes |
|---|---|---|
| `getPlaces()` | `GET /places` | |
| `getPlace(id)` | `GET /places/{site_id}` | |
| `getPack(id, { knownVersion })` | `GET /pack/{site_id}` | Sends `If-None-Match`; returns `not-modified` on 304 |
| `downloadTripPack(request, { ai })` | `POST /pack/{site_id}` | Can be slow while the server's model writes; `ai: false` gets rule-based text |
| `getDelta(id)` | `GET /delta/{site_id}` | |

Errors are thrown as `ApiError` with the HTTP `status` and FastAPI's `detail`.

### Types

`src/api/types.ts` mirrors the backend's Pydantic models (`backend/src/trip_advisor/schemas/`) and
exported JSON Schemas (`backend/data/schemas/`). When the backend changes a schema, update this file
to match. Do not add fields the backend does not send.

## Offline data

`src/db/db.ts` opens the `trip-advisor` IndexedDB database:

| Store | Key | Holds |
|---|---|---|
| `trips` | `id` (random UUID), index `bySite` | A `SavedTrip`: the full `TripPack` from `POST /pack`, kept unchanged |
| `deltas` | `siteId` | The newest `Delta` fetched for each site |

A saved trip's `tripPack.delta` is the weather and news its advice was written from. Newer deltas go
in `deltas` (`saveDeltaIfNewer` keeps only a newer `generated_at`), so the app can later compare the
two and tell the traveller what changed. Saving a trip also asks the browser for persistent storage,
so the data is less likely to be evicted.

To change the database layout, bump `DB_VERSION` and add a new `case` to the `upgrade` switch.

## Service worker

`registerType: 'prompt'`: a new app version is installed in the background and only activates when
the traveller taps "Update" (`src/pwa/PwaStatus.tsx`), so the app never reloads unexpectedly.
The service worker precaches the app shell only. It does not cache API responses; trip data
is kept in IndexedDB on purpose.

The manifest icon is a single SVG (`public/icon.svg`). Some platforms (notably older iOS) want
PNG icons at 192 and 512 px; add those before release.

## Layout

```
src/
  main.tsx               entry: mounts the router
  router.tsx             routes
  index.css              Tailwind import and base styles
  env.d.ts               env and PWA module types
  api/types.ts           backend data types
  api/client.ts          fetch wrapper and one function per endpoint
  db/db.ts               IndexedDB: saved trips and latest deltas
  hooks/useOnlineStatus.ts
  pwa/PwaStatus.tsx      service worker registration and update notice
  components/AppShell.tsx  header, online badge, bottom nav
  pages/                 HomePage, TripsPage (placeholders), NotFoundPage
```
